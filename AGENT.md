🎯 О проекте
1C AI Assistant — внутренний корпоративный ассистент, который позволяет пользователям общаться с базой 1С на естественном языке через чат. Ассистент формирует запросы к 1С, получает данные и генерирует человекочитаемый ответ с помощью LLM.

Ключевые требования:

Соблюдение прав доступа пользователей 1С (роли и RLS) — критично.

Кроссплатформенность (Windows и Linux).

Возможность подключения внешних MCP-клиентов (Cursor, Claude Desktop).

Read-only по умолчанию. Запись — только после отдельного этапа.

Целевая аудитория: сотрудники компании, работающие с 1С.
Владелец: внутренняя команда разработки.

Разделение ответственности:

MCP-сервер на C# — предоставляет инструменты (tools) по протоколу MCP, транслирует вызовы в HTTP-запросы к 1С. Не знает о внутренностях 1С.

Расширение 1С — HTTP-сервисы, которые принимают запросы, проверяют права пользователя, выполняют операции и возвращают данные. Устанавливается как .cfe, не модифицирует основную конфигурацию.

Чат — отдельное приложение, которое использует LLM и MCP-сервер.

LLM — работает на стороне AI-клиента (не внутри MCP-сервера).

Поток вызова:

Пользователь пишет сообщение в чат.

LLM вызывает инструмент через MCP-протокол.

MCP-сервер транслирует вызов в HTTP-запрос к расширению 1С.

Расширение 1С проверяет права и выполняет операцию.

MCP-сервер возвращает данные LLM.

LLM формирует ответ пользователю.

🔐 Безопасность и права доступа
Это критическая часть проекта. Нарушение прав доступа — блокер для релиза.

Принципы
Права пользователя 1С применяются всегда. Никаких исключений.

Read-only по умолчанию. Запись включается явно и только на Этапе 3.

Минимум привилегий. Сервисная учётка 1С имеет только необходимые права.

Аудит всего. Каждый вызов инструмента логируется: кто, когда, что, результат.

Аутентификация
MCP-сервер принимает JWT-токен пользователя.

Токен передаётся в расширение 1С в заголовке Authorization: Bearer <token>.

Расширение 1С валидирует токен и определяет пользователя.

Разграничение прав
Основной механизм: расширение 1С выполняет запросы от имени пользователя через COM-соединение или с явной проверкой ПравоДоступа().

RLS (Row-Level Security): обеспечивается платформой 1С при выполнении запросов от имени пользователя.

Дополнительно: MCP-сервер ведёт белый список инструментов для каждого пользователя (хранится в БД или конфиге).

Запрещено
❌ Выполнять запросы под сервисной учёткой без проверки прав.

❌ Возвращать данные, которые пользователь не имеет права видеть.

❌ Реализовывать собственную логику ролей, если её можно делегировать 1С.

❌ Логировать персональные данные в открытом виде.

Принципы дизайна

Компактные ответы: TSV для табличных данных, JSON для структурных.

📄 Контракт HTTP-сервисов 1С
Все эндпоинты — POST, JSON-запрос, JSON/TSV-ответ.

Базовый URL: https://<1c-server>/<base>/hs/mcp/<service>/

Заголовки
text
Authorization: Bearer <JWT>
Content-Type: application/json
X-Request-Id: <uuid>            // для трассировки
Формат ответа
json
{
"success": true,
"data": "...",
"error": null,
"requestId": "uuid"
}
При ошибке:

json
{
"success": false,
"data": null,
"error": {
"code": "ACCESS_DENIED",
"message": "Нет прав на чтение справочника Номенклатура"
},
"requestId": "uuid"
}
Коды ошибок
Код	Описание
ACCESS_DENIED	Нет прав
NOT_FOUND	Объект не найден
INVALID_QUERY	Ошибка в запросе
TIMEOUT	Превышено время выполнения
INTERNAL_ERROR	Внутренняя ошибка 1С
Пример: execute_query
Запрос:

json
{
"query": "ВЫБРАТЬ ПЕРВЫЕ 100 Номенклатура, Количество ИЗ РегистрНакопления.ТоварыНаСкладах",
"format": "tsv",
"limit": 100
}
Ответ:

json
{
"success": true,
"data": "Номенклатура\tКоличество\nТовар А\t10\nТовар Б\t5",
"error": null,
"requestId": "..."
}
🚀 План развития
Этап 1: Фундамент (read-only)
Цель: работающий ассистент для чтения данных.

MCP-сервер на .NET 10 с stdio-транспортом через ModelContextProtocol.AspNetCore.

Расширение 1С с 5–7 read-only HTTP-сервисами.

Аутентификация через JWT.

Проверка прав пользователя.

Чат-интерфейс (базовый).

Интеграция с одной LLM.

Логирование вызовов.

Этап 2: MCP-интеграция
Цель: подключение внешних MCP-клиентов.

HTTP/SSE транспорт для MCP-сервера.

JWT-аутентификация для HTTP.

Публикация всех инструментов через MCP.

Проверка совместимости с Cursor и Claude Desktop.

Этап 3: Запись и действия
Цель: ассистент выполняет действия.

Инструменты записи (создание, изменение, проведение).

Human-in-the-loop подтверждение опасных операций.

Расширенный аудит.

Этап 4: Продукт
Цель: полноценный внутренний продукт.

Админ-панель.

Мультибазовость.

Поддержка локальных LLM.

Метрики и мониторинг.

SSO (Entra ID, Keycloak).

Расширение 1С валидирует токен и определяет пользователя.

Разграничение прав
Основной механизм: расширение 1С выполняет запросы от имени пользователя через COM-соединение или с явной проверкой ПравоДоступа().

RLS (Row-Level Security): обеспечивается платформой 1С при выполнении запросов от имени пользователя.

Дополнительно: MCP-сервер ведёт белый список инструментов для каждого пользователя (хранится в БД или конфиге).

Запрещено
❌ Выполнять запросы под сервисной учёткой без проверки прав.

❌ Возвращать данные, которые пользователь не имеет права видеть.

❌ Реализовывать собственную логику ролей, если её можно делегировать 1С.

❌ Логировать персональные данные в открытом виде.

📄 Контракт HTTP-сервисов 1С
Все эндпоинты — POST, JSON-запрос, JSON/TSV-ответ.

Базовый URL: https://<1c-server>/<base>/hs/mcp/<service>/

Заголовки
text
Authorization: Bearer <JWT>
Content-Type: application/json
X-Request-Id: <uuid>            // для трассировки
Формат ответа
json
{
"success": true,
"data": "...",
"error": null,
"requestId": "uuid"
}
При ошибке:

json

"success": false,
"data": null,

"requestId": "uuid"
}

INTERNAL_ERROR	Внутренняя ошибка 1С

✅ Правила работы для LLM-агента
Что делать
Читай AGENT.md полностью перед началом работы.

Соблюдай архитектурные границы. MCP-сервер не знает о 1С, 1С не знает о LLM.

Проверяй права доступа в каждом инструменте. Это не опционально.

Пиши тесты на каждый новый инструмент и на каждый HTTP-эндпоинт.

Документируй контракты (HTTP, MCP) в docs/.

Используй структурированное логирование (Serilog) с RequestId.

Следуй C#-соглашениям: PascalCase для публичных членов, _camelCase для приватных полей, I для интерфейсов.

Соблюдай BSL-соглашения: префикс АИ_ для объектов расширения, комментарии на русском.

Использовать .NET 10 SDK для всех проектов. Версия зафиксирована в global.json.

Использовать C# 14 — extension members, field, null-conditional assignment.

Использовать ModelContextProtocol.AspNetCore версии, совместимой с .NET 10.

Проверять breaking changes при обновлении зависимостей.

Использовать ASP.NET Core 10 для чат-бэкенда и MCP-сервера.
